The problem

The second factory creates concerns no single factory can own.

A factory is deliberately repo-scoped and stateless. Everything below belongs to the host, and until now it lived in someone's memory.

01

Which engine version runs

One shared install, used by every timer. Nobody records it; upgrading is "remember to reinstall".

02

Host settings in public repos

Local model endpoints, hand-picked dashboard ports, and bind hosts committed to .factory.toml — duplicated and drifting.

03

Stale generated artifacts

systemd units bake in PATH at install time. Issue templates, labels, and new config keys are copied once and never refreshed.

04

No fleet answer

systemctl --user list-timers plus one browser tab per dashboard. No single answer to "is everything healthy?"

Ownership model

Classified by where it lives, not by feature.

Every setting District touches is either host-side or committed to a repo. The split is the product.

District owns — host-side, never committed

  • agent-factory install and upgrade
  • triage endpoint and model
  • worker / reviewer argv defaults
  • dashboard port allocation, timer cadence, bind host
  • systemd units, rendered via factory install
  • registry of managed repos
  • GitHub labels, re-applied idempotently
  • supply-chain policy (minimum package age)
  • consecutive-failure cap on each timer

Factory owns — committed to its repo

  • [[gate.check]] commands
  • [leak_scan] excludes
  • [repo].upstream for forks
  • .github/ISSUE_TEMPLATE/agent_task.md
  • .factory-lessons.md
  • .gitignore lines
  1. District writes committed files exactly once, at onboarding, and only reports drift afterwards.
  2. District rewrites host-side artifacts on every apply without asking.
  3. District never commits to a managed repo. It prints the commit line.
Commands

Six verbs. Each one shells out to factory, gh, and git.

District uses only the public agent-factory CLI and never reimplements a factory command. If it needs a per-repo fact, the fix is a flag on factory.

district add
Onboard a path or URL, or adopt a repo that already has .factory.toml. Detects fork parent, ecosystem, and the next free port; proposes gate checks from CI; lifts host-owned keys out of the repo file.
district apply
Reconcile the host to the registry. Re-renders units, ensures labels, runs doctor, enforces the failure cap and supply-chain policy. --upgrade reinstalls the engine so every timer picks it up on the next tick.
district status
One table, one screen, one exit code. Version, timer, last pass, tickets in flight, escalations, first-gate pass %, bounce rate, upstream drift.
district metrics
Per-factory size, people, velocity, work, quality, resolution, and traffic — sourced from git and gh, never estimated. Cached hourly.
district dashboard
Serve the District Atlas. --host 0.0.0.0 enables read-only LAN viewing at a numeric-IP URL with the actual port, never remote management; a LAN URL stays read-only even on the host. Manage and detect require direct HTTP to numeric loopback or localhost with the actual server port (default http://127.0.0.1:8760). DNS aliases and reverse proxies are unsupported; forwarded headers fail closed. Authorized actions run the CLI as a subprocess with bounded sanitized diagnostics.
district rm
Disable and delete the units, drop the registry entry. Repo files untouched; the factory can be re-added later.

Operational model

One classification for the CLI and dashboard.

Machinery findings, project context and observation quality are separate. The existing full snapshot remains the source; missing execution telemetry is explicit, not reconstructed from artifacts.

DimensionValues
Operatingrunning · scheduled waiting · deliberately paused (recorded intent only) · capped · unexpectedly stopped (authoritative evidence only) · unknown
Executionstage-active · known wait · blocked · completed · failed · interrupted · unknown
Observationfresh · stale · partial · unavailable; source times are retained across rereads

district status --json is keyed by repository slug. Each entry exposes schema_version, operating_state, execution_state, observation, assessment, findings, sources, reported executions, resources and explicit unknowns, alongside existing table, snap, error and cached metrics context. The obsolete health/reasons fields are removed. The complete normalized D02 contract is in OPERATIONS-CONSOLE-SPEC.md §6.1 and district/health.py.

Exit 0: every entry normal, or an empty fleet ({} in JSON). Exit 1: any supported operational attention. Exit 2: unknown observation/state without attention; command-usage errors also use 2. Attention takes precedence over unknown, which remains visible in each JSON entry. Existing engines without execution telemetry normally report partial/unknown, not silently healthy.

The browser receives a bounded, sanitized projection of that same classification, not raw CLI snapshots or host configuration. One server-owned collector runs schema-1 factory dashboard --runtime-json about every five seconds and the full GitHub/config snapshot every 60 seconds, with a four-second per-factory timeout, eight-worker concurrency bound and no overlapping work per factory. Browser requests only read the cache. /api/fleet reports its revision and bounds; each entry retains source and collection ages plus at most 512 deduplicated events and the producer's history completeness, truncation and reconnect gaps. Findings retain scope, source timestamps, observation quality and evidence; omissions are explicit and never change the assessment. See OPERATIONS-CONSOLE-SPEC.md §§6.2 and 8.

Ready-for-human tickets, parked upstream project work, review bounce, legitimate gate/review rejection and ordinary CI/capacity/resource waits do not independently create findings. A failed snapshot is an observation gap, not proof of stopped dispatch. apply retains its separate reconciliation exit contract and failure-cap policy.

Failure cap

Ten consecutive failed passes and District disables the timer. A pass that fails every ten minutes otherwise burns model spend indefinitely. apply re-enables it once the cause is fixed.

Supply-chain policy

Workers install packages with the operator's credentials. District checks the host-wide minimum package age for uv, npm, and cargo. Missing policy is a WARN, never a silent skip.

Adding a repo never hides a bad floor

First-gate pass % and review bounce rate stay on the fleet table. A fleet that scales a mediocre pipeline scales mediocrity.

Install

Python 3.11+, one dependency, a stdlib HTTP server.

Requires agent-factory on the host and the gh CLI authenticated.

shell
$ npx skills add mikeroysoft/district
$ uv tool install git+https://github.com/mikeroySoft/district
$ district add ~/dev/owner/repo        # or a GitHub URL; adopts an existing .factory.toml
$ district apply                        # reconcile units, labels, doctor, caps, policy
$ district dashboard --install          # district-dashboard.service + hourly metrics timer
$ district status

The host config file at ~/.config/agent-factory/config.toml is the registry. No second store. A repo is managed iff it has a [repo."owner/name"] table with a path.
