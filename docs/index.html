The problem

The second factory creates concerns no single factory can own.

Repository autonomy is useful. Duplicating host configuration, upgrade procedures, and operational checks across every repository is not.

01

One place for host settings

Keep model endpoints, worker defaults, dashboard ports, and timer cadence in the host registry, not scattered across public repositories.

02

Repeatable maintenance

Reconcile generated units and labels, check prerequisites, and upgrade the shared engine without replacing each repository's own rules.

03

Bounded failure, explicit recovery

Cap repeatedly failing timers and check package-age policy. Restore a capped factory only after an explicit reset pass succeeds.

04

A fleet answer you can inspect

See operational findings and source freshness together. A review requesting changes is project work, not automatically broken machinery.

Ownership model

Classified by where it lives, not by feature.

Every setting District touches is either host-side or committed to a repo. The split is the product.

District owns — host-side, never committed

  • mikeroySoft/factory install and upgrade
  • triage endpoint and model
  • worker / reviewer argv defaults
  • dashboard port allocation, timer cadence, bind host
  • systemd units, rendered via factory install
  • registry of managed repos
  • GitHub labels, re-applied idempotently
  • supply-chain policy (minimum package age)
  • consecutive-failure cap on each timer

Factory owns — committed to its repo

  • [[gate.check]] commands
  • [leak_scan] excludes
  • [repo].upstream for forks
  • .github/ISSUE_TEMPLATE/agent_task.md
  • .factory-lessons.md
  • .gitignore lines
  1. District writes committed files exactly once, at onboarding, and only reports drift afterwards.
  2. District rewrites host-side artifacts on every apply without asking.
  3. District never commits to a managed repo. It prints the commit line.
Commands

Eight verbs. Each one shells out to the host tools it checks or manages.

District never imports from mikeroySoft/factory and never reimplements a factory command. If it needs a per-repo fact, the fix is a flag on factory.

district add
Onboard a path or URL, or adopt a repo that already has .factory.toml. Detects fork parent, ecosystem, and the next free port; proposes gate checks from CI; lifts host-owned keys out of the repo file.
district apply
Reconcile units, labels, doctor checks, failure caps, and host policy. Hourly reconciliation is available through dashboard --install. --upgrade waits for all managed passes before replacing the shared engine; --reset SLUG requires a successful pass before restoring a capped timer.
district doctor
Check District's host prerequisites, registered repository remotes, dashboard ports, package policy, and units. Reports every check as PASS, WARN, or FAIL.
district status
Operating state, execution state, observation quality, and evidence-backed findings, with version and project metrics alongside. Text or --json; exit 0 for normal, 1 for operational attention, 2 for unknown without attention.
district metrics
Per-factory size, people, velocity, work, quality, resolution, and traffic — sourced from git and gh, never estimated. Cached hourly.
district dashboard
Serve the shared cached fleet and scoped console. Atlas and management remain at the default route until cutover. Optional LAN viewing is read-only; management stays on direct localhost access. See current routes and access boundaries.
district update
Resolve an official ref to one immutable SHA, require the successful ci.yml test job for that SHA, and transactionally replace only District's uv tool. Supports query-only --dry-run, machine-readable --json, and retained offline --rollback; Factory and unit files are unchanged.
district rm
Disable and delete the units, drop the registry entry. Repo files untouched; the factory can be re-added later.

Merged · shared state

Collect once. View anywhere.

One server-owned collector refreshes runtime observations about every five seconds and full snapshots every minute. Extra browser tabs read the cache instead of multiplying Factory and GitHub calls.

Merged · scoped navigation

Keep your place.

Overview, Flows, and Brief routes share all-factory or single-factory scope. Deep links, browser Back, scroll restoration, and focus-preserving updates keep navigation usable while the fleet changes.

Merged · read-only LAN

View remotely. Manage locally.

Opt into LAN viewing without exposing host controls. Remote requests cannot run management or detection; browser data is bounded and sanitized rather than a copy of host configuration.

Try the current console: after starting the dashboard, open http://127.0.0.1:8760/?view=overview. Change view to flows or brief for the shared scoped views. Detailed flow lanes, the evidence panel, and the full Brief are still planned. Atlas and existing management remain at / and /legacy.

LAN viewing requires an explicit bind such as --host 0.0.0.0. Manage and detect require direct HTTP to numeric loopback or localhost at the actual server port. LAN URLs remain read-only even on the host; DNS aliases and reverse proxies are unsupported, and forwarded headers fail closed. Network policy.

Design decisions

What we chose. What we chose not to build.

District started with a city-shaped Atlas. The next operating surface puts work and evidence ahead of architecture and repository size.

Host infrastructure, not repo control

District owns the shared machinery. Gate commands, reviewable files, and project decisions stay with each Factory. It shells out to public commands rather than importing the engine's internals.

Operational attention, not project noise

A failing runner and a failing product test are different events. Ordinary CI waits, review revisions, and human decisions do not independently turn into fleet incidents.

Unknown is an answer

Missing or stale observations stay visible. Re-reading a cache does not make old evidence fresh, and an unavailable snapshot does not prove that a dispatcher stopped.

Evidence before animation

The approved graphical direction uses equally weighted factories and concurrent execution lanes, not taller buildings for bigger repos. Motion will describe observed activity, never fictional progress or an invented ETA.

Read the approved operations-console specification · One operator, one Linux host. Multi-host orchestration, team management, and an LLM-generated Brief are outside this console's scope.

Operational model

One classification for the CLI and dashboard.

Machinery findings, project context and observation quality are separate. CLI status takes one bounded runtime/full collection round through the same source adapters as the server. Missing execution telemetry is explicit, not reconstructed from artifacts.

DimensionValues
Operatingrunning · scheduled waiting · deliberately paused (recorded intent only) · capped · unexpectedly stopped (authoritative evidence only) · unknown
Executionstage-active · known wait · blocked · completed · failed · interrupted · unknown
Observationfresh · stale · partial · unavailable; source times are retained across rereads

Exit 0: every entry normal, or an empty fleet. Exit 1: any supported operational attention. Exit 2: unknown observation or state without attention. Attention takes precedence, but unknowns remain visible. Engines without execution telemetry report partial/unknown rather than silently healthy.

The CLI and dashboard share source adapters and classification. Runtime and full snapshots refresh independently; producer timestamps, record-level quality, bounded history, and gaps remain explicit. A slow full snapshot does not need to block publication of runtime evidence.

Integrating with District? The source and JSON contract documents observation bounds, findings, and the migration from the old health/reasons fields. district status --json exposes the normalized state keyed by repository slug.

Failure cap

Ten consecutive failed passes disable a timer. Fix the cause, then use district apply --reset SLUG: the timer resumes only after a successful pass.

Supply-chain policy

Workers install packages with the operator's credentials. District checks the host-wide minimum package age for uv, npm, and cargo. Missing policy is a WARN, never a silent skip.

Context without false alarms

First-gate pass rate and review bounce remain useful project metrics. They do not independently label the underlying machinery unhealthy.

Install

Python 3.11+, one dependency, a stdlib HTTP server.

For a Linux host with user systemd, Factory, git, and an authenticated gh CLI. Runtime execution detail requires a Factory build supporting dashboard --runtime-json.

shell
$ npx skills add mikeroysoft/district
$ uv tool install git+https://github.com/mikeroySoft/district
$ district doctor                       # check this host before onboarding
$ district add ~/dev/owner/repo        # or a GitHub URL; adopts an existing .factory.toml
$ district apply                        # reconcile units, labels, doctor, caps, policy
$ district dashboard --install          # dashboard + hourly metrics and apply timers
$ district status
$ district update --dry-run             # exact SHA, CI eligibility, service plan; no mutation

The host config file at ~/.config/factory/config.toml is the registry. No second store. A repo is managed iff it has a [repo."owner/name"] table with a path.

Optional Factory features survive every shared, host-wide engine reinstall when selected in the registry, for example:
[defaults]
factory_extras = ["atlas"]
Omit the setting or use an empty array to keep installing bare Factory; run district apply --upgrade to apply the selection to the one engine used by every managed repository.

District self-update supports only a non-editable uv install from the official repository. It prepares the target before downtime, runs replacement and recovery from a retained stdlib helper outside the managed environment, and keeps the prior successful installation for district update --rollback. Metadata lives under ${XDG_STATE_HOME:-~/.local/state}/district/update, never in Factory's registry. A source checkout can bootstrap the installed tool with uv run python -m district update --to <eligible-sha> --yes.
